## 0. 当前只读版如何开启

1. 保持 Desktop 运行，打开「设置 → Web 访问」。将电脑和浏览器设备接入同一个**可信私有网络**。
2. 页面会自动选取本机私有 IPv4 地址；有多张网卡时，在「本机网络地址」中选要连接的那一个。点击「生成配对码」会一并配置并开启网关；不需要 HTTPS 证书或先保存配置。若无可用私网地址，请先连接局域网，或在高级配置中使用已有可信 HTTPS 代理。
3. 在同网段浏览器打开页面显示的完整地址，输入 Desktop 显示的一次性配对码。当前只能查看当前与归档项目的**名称和本机路径**，不读取文件内容、不修改项目、不运行任务；授权 1 小时后失效，配对码 5 分钟内有效且只能使用一次。
4. 可在设置页撤销单个浏览器或全部浏览器，也可关闭 Web 访问。退出或重启 Desktop 后，服务和授权不会自动恢复；下次需要重新开启并配对。若浏览器访问失败，请核对所选网卡地址、两台设备的网络连通性和操作系统防火墙是否允许该端口。

**安全提醒：局域网 HTTP 不加密。** 同网段有能力窃听或篡改流量的设备可能截获配对码、浏览器会话、项目名称和本机路径。仅在可信私有网络中启用，不要做公网端口转发；需要保密时继续使用可信 HTTPS 代理。代码回归并不代替真实浏览器、网络与安全验收。


## 1. 已确认的产品范围

- 单人使用，Desktop 常驻，通过 LAN 或 VPN 访问；不是 headless 服务、多人 SaaS 或云端复制实例。
- 网页使用真正的网页控件，目标覆盖当前发行配置启用的完整内置功能，不以聊天 MVP 或 WebRTC 桌面镜像替代。
- Desktop Main 及其现有 Runtime、领域服务是同一套业务事实源。两端共用项目、历史、运行任务和文件，不创建第二套 Agent 后端，不复制业务数据库后双写。
- 两端可以停留在不同页面、不同会话。当前页面、当前选择、输入草稿、尚未提交的编辑及界面焦点按客户端独立；不得广播桌面导航来强迫网页切页。
- 已提交业务设置需要同步；**不承诺主题、布局、缩放、展开状态或其他界面偏好跨端同步**。以后若要同步，须另行定义作用域和冲突语义。
- 第三方插件逐步适配：旧插件的桌面行为保持，未适配网页的插件明确提示不兼容，不在网页再次执行完整 `activate()`。
- 由第一方预设插件承载的设计、浏览器、媒体等内置能力仍属于完整功能目标，不能借“第三方插件逐步适配”排除。
- 原生权限可以在宿主电脑确认，但网页必须显示真实的等待、拒绝或不可用状态；要求宿主确认不等于网页已经完成该操作。

本合同按业务目标拆分验收，不能用某个传输接口覆盖率或聊天链路通过率宣称“完整支持”。实施时应对照当前 Desktop 的内置入口逐项登记；发现矩阵未列明的内置入口应补充，不得静默省略。

## 2. 架构与状态所有权

### 2.1 唯一执行所有者

Main 负责或统一管理 Runtime、项目、业务配置、任务、Team、调度、审批、PTY、资源与授权的生命周期。客户端订阅只拥有观察关系，不拥有这些业务对象的生死。

现有插件执行包含 Renderer 侧贡献注册；实施必须保留一个受宿主管理的执行所有者，而不是简单声称所有插件代码已经运行在 Main。网页仅加载已适配的展示面，不重复注册工具、Hook、Action、调度器或长驻服务。

### 2.2 统一业务合同，不建立任意 IPC 代理

拟议调用关系：

```text
共享展示组件与客户端业务模型
  ├─ Desktop 平台适配 → Electron IPC 入口 ─┐
  └─ Web 平台适配 → 认证 Web 业务入口 ────┤
                                       ↓
                     显式操作目录、校验、授权及领域服务
                                       ↓
                        同一 Main / Runtime / 持久化
                                       ↓
                 领域快照与事件 → 各客户端独立订阅和投影
```

- 现有 [DesktopApi 聚合](../src/preload/api.ts)、[API 工厂装配](../src/preload/index.ts) 和已提取的 [HostTransport](../src/shared/host-transport.ts) 是复用入口，不是网络公开清单。`channel: string` 不能成为浏览器请求任意宿主功能的授权依据。
- Web 入口逐项登记业务操作、输入输出校验、错误、权限、副作用、幂等和事件。未知操作默认拒绝；请求身份、来源和授权由宿主派生，不能由浏览器填写。
- IPC 与 Web 各自装配同一领域服务；遵循 [IPC 目录规则](../src/main/ipc/AGENTS.md)，不得反向调用 handler、伪造 `WebContents` 或绕过原有权限校验。
- 禁止任意 IPC 名、任意 `executeJavaScript`、本机 Action RPC token、内部 capability session 或原始凭据透传。已有本机 RPC 不改成公网或局域网通用入口。
- 复用 [theme-ui 公开展示面](../../../packages/theme-ui/package.json) 和现有领域模型；先隔离 Electron、资源 URL、文件选择等依赖，再接入 Web 启动目标。不能直接复制整套 Desktop 页面形成第二套长期分叉实现。
- [远程控制 ADR](../../../docs/adr/0078-remote-control-transport.md) 仅提供既有背景。当前协议、恢复能力与授权范围以源码及实际测试为准；本文不将已有 Relay 或 ACK 缓存视为完整 Web 合同。

### 2.3 同步的边界

- 宿主权威状态：已提交项目、会话与消息、回合、已接受发送队列、文件、业务设置、任务、审批结果、PTY 和插件安装状态。
- 客户端本地状态：路由、当前选择、草稿、光标、待提交编辑、滚动位置和局部加载状态。现有 [chat atoms](../src/renderer/shared/store/chat-atoms.ts) 中的状态须按此分类，不能整体镜像。
- 浏览器刷新只能重新认证、恢复订阅和对账，不重放发送、审批、终端输入或安装等副作用。
- 稳定的业务对象标识与进程内 Runtime 标识必须区分。重新打开或重启后由宿主解析映射，不能依赖桌面当前活动会话，也不能把客户端提交的任意文件路径当作会话身份。

第一方能力若因平台或依赖缺失而不可用，须展示准确原因和下一步；这属于真实能力状态，不是省略该能力的依据。尚未适配的内置功能仍是本项目未完成项。

## 4. 平台语义与插件兼容

### 4.1 设备归属

| 能力 | 执行位置 | 网页合同 |
| --- | --- | --- |
| 读取项目、执行工具/终端、SSH、调度、生成与导出 | **主机执行** | 文件、进程、费用与外部副作用发生在宿主或已有远程项目上；网页不是本地文件沙箱。 |

任何端口都不得以无操作函数、空对象或固定成功值填平能力缺口。拟议能力描述至少区分“可用”“等待宿主确认”“需要配置”“平台不支持”“尚未适配”，名称与最终 Schema 待实现确定。

### 4.2 插件单一执行、多端展示

- 保留旧插件的桌面入口与原有权限模型；网页能力必须显式适配，不按“使用 React”推断兼容。
- 插件执行 owner 与 UI 实例生命周期分开。关闭网页、切换路由、加载两个标签页均不重新注册执行贡献，也不停止独立的桌面执行。
- 未适配第三方插件仍可显示名称、版本、宿主启停状态和不兼容原因；不能在网页默默执行旧入口尝试兼容。
- 网页展示不得因同源 Cookie 继承完整所有者权限。第三方展示使用隔离环境和受限桥；能力由宿主检查，不由插件自行授予。
- 第一方设计、媒体、浏览器预设需按矩阵拆分执行与展示，保留原桌面常用流程。网页支持不能靠再次完整 `activate()` 实现。
- 网页兼容声明、入口、桥接权限和版本迁移均尚未定稿。涉及 SDK/manifest 公开变更时按[插件规则](../../../packages/plugins/AGENTS.md)同步正式作者文档与兼容测试；本文件不定义一个已经可用的新 SDK。

## 5. 拟议业务协议与恢复合同

### 5.1 操作目录与版本

每个被公开的业务操作必须声明：稳定名称、Schema 版本、参数和返回值校验、所需权限、目标对象、只读/写入/执行分类、幂等策略及可订阅结果。下列字段是拟议概念，不是已有 wire API：

| 概念 | 必须保证的语义 |
| --- | --- |
| 请求 ID 与操作 ID | 请求 ID 用于一次传输关联；操作 ID 在超时、刷新和重连后仍标识同一个副作用。不能把重连生成的新请求 ID 当作新业务意图。 |
| 客户端与授权身份 | 由认证会话绑定，不能相信客户端自报；同一用户的两个客户端可以独立撤销。 |
| 业务目标 | 稳定项目/会话/任务/资源引用；Runtime 实例 ID 由宿主解析。失效引用明确报错，不回退到当前活动会话。 |
| 资源版本与期望版本 | 快照给出当前版本，写入携带读取基线。版本不匹配返回冲突和可重新读取的状态，不静默最后写入覆盖。 |
| 宿主世代与事件游标 | 区分宿主重启、事件流重建和普通重连；旧游标不能错误地接到另一条流。 |
| 操作回执 | 区分未接受、已接受、排队、执行中、等待确认、成功、失败、取消与结果待核实。收到请求不等于副作用已经完成。 |

IPC 保持既有行为的同时，Web 新合同不得绕过现有只读、权限、工具审批、会话所有权或失败诊断。协议升级须有兼容协商；未知版本默认拒绝，不静默降级到任意调用。

### 5.2 快照、订阅与断线

- 快照与事件订阅必须有无缝衔接点：在生成快照前建立缓冲或使用一致版本/游标，避免加载过程中丢事件；重叠事件按身份去重。
- 各领域明确自己的有序流、版本和失效策略，不假定全应用有一个全局序号。模型、工具、错误、终态保持各自语义，不凭文本增量推断成功。
- 缓冲有界。游标过期或事件缺口必须返回“需要重新同步”，拉取快照后再续流；现有连接内缓存不能是唯一事实源。
- 按客户端和订阅 ID 管理清理。退订只释放该订阅、watch 或展示资源；不得误停共享任务或另一客户端订阅。
- 断线不自动重发 prompt、审批、终端输入或付费生成。客户端先查询操作回执；状态无法确定时显示待核实，不能伪报成功或悄悄再做一次。
- 接受发送、任务及审批的权威状态在宿主；订阅连接不能拥有执行生命周期。宿主重启后哪些工作能继续、哪些只能读取最终状态，须逐域定义并测试。

### 5.3 并发写入与幂等

- 文件、设置、设计文档、项目和任务定义均采用领域适用的版本比较。外部编辑、重命名、删除与 SSH 变更也会使基线失效。
- 同一操作 ID、相同有效输入返回原回执；同 ID 不同输入拒绝。去重范围绑定授权与业务目标，不能用另一授权的 ID 读取结果。
- 已接受写入及执行需要明确的记录持久化点和崩溃窗口。外部系统不可回滚的副作用不承诺绝对“恰好一次”；无法核实结果时禁止自动重做。
- 交互回复通过宿主原子状态转换解决竞答；PTY 输入按控制权和序号确认，不把普通 RPC 重试策略用于终端字节。
- 去重记录保留期、游标窗口和宿主重启后的回执查询边界是实施前需要定稿的协议事项。

## 6. LAN/VPN 部署与安全边界

### 6.1 监听与传输

- **默认关闭且不监听。** 用户在 Desktop 明确生成配对码时，HTTP 直连只绑定当前本机网卡上选定的私有 IPv4 地址和端口；网卡在启动前消失即失败，不改绑其他地址或 `0.0.0.0` / `::`。已有可信 HTTPS 代理仍只转发到 Desktop 回环监听器。
- 私网 HTTP 直连不要求证书，但不保护同网段上的配对码、Cookie、项目名称及路径免遭窃听/篡改；只适合可信私有网络，不可开放公网或映射路由器端口。需要传输保密时使用可信 HTTPS 入口。局域网/VPN、配对、Host/Origin 或 CSRF 均不能替代 TLS。
- HTTPS 入口是可选的已有代理或 HTTPS VPN，由用户配置公网 HTTPS Origin；TLS 在该入口终止，控制页和 API 转发到 Desktop 回环网关。Vetta 不管理证书或私钥，不能根据客户端的 `Forwarded` 或 `X-Forwarded-*` 动态决定可信来源。
- HTTP 和 WebSocket upgrade 校验配置中确定的 Host；修改请求及 WebSocket 校验精确 Origin，不动态反射白名单。WS 拒绝缺失或 `null` Origin；普通导航与状态修改应分别处理，不能一概把缺 Origin 当合法修改。

### 6.2 身份、授权与跨站防护

- 桌面确认短期、一次性的配对请求，再换取独立、可撤销的浏览器会话；浏览器不取得本机 RPC、Provider 或插件执行凭据。
- HTTPS 入口使用 host-only、`HttpOnly`、`Secure`、`SameSite=Strict`、`__Host-` 前缀的 Cookie；私网 HTTP 入口使用独立 Cookie 名，不设置 `Secure` 或 `__Host-`，否则浏览器不会保存会话。两者均用精确 Host/Origin、同源 CSRF 与可撤销的短期授权，配对凭据不写日志、query 参数或长期页面存储；这些机制都不能让 HTTP 明文变为安全传输。
- Host/Origin 是防跨站与 DNS rebinding 的补充，不是认证。CORS 不使用任意来源；认证失败、过期、撤销与权限不足有明确结果。
- 历史、快照、重放、资源请求、发送、停止和审批均重新检查授权。完整功能不代表绕过权限，也不代表暴露旧凭据；授权提示必须说明真实 Agent/终端可改文件、调用外部服务并产生费用。
- 项目选择与会话访问授权**不等于工具级项目沙箱**。未建立执行隔离前不得宣称权限只限某目录；浏览器或聊天工具也不能自行扩大网关授权。

### 6.3 断线、停止、撤销与关闭

| 情况 | 必须实现的行为 |
| --- | --- |
| 普通断线/刷新 | 保留已接受任务及回执，释放连接级资源；重新认证后恢复。是否保留 PTY 及多久，由领域生命周期合同决定。 |
| 停止指定工作 | 对已授权对象发出取消，最终以宿主终态为准；停止请求已收到不能伪装为任务已经停止。 |
| 撤销浏览器授权 | 立即拒绝新操作，关闭该授权连接并失效恢复凭据和资源访问；取消该授权拥有的排队工作、回合、待审批及执行租约，不误停独立本地工作。 |
| 关闭 Web 功能或停用管理插件 | 宿主停止监听、撤销 Web 授权并清理对应资源；异步开启途中停用也不能留下稍后启动的监听器。不能依赖页面卸载回调。 |
| 已接受的持久自动化 | 必须区分远程授权拥有的临时工作与明确转为宿主持有的长期计划；撤销时如何处理已启用计划需定稿，不能默认为无限继续。 |

撤销不是回滚：已写文件、已发网络请求等不可撤销副作用需准确保留状态并提示。浏览器不能通过修改设置把自身重新授权。

### 6.4 受控资源与不可信内容

- 静态服务只发布指定 Web 构建产物。项目文件、配置、用户状态目录和插件数据不能直接挂成静态目录。
- 文件、媒体、插件资产和设计产物映射为宿主验证的资源引用；每次访问检查授权、归属、真实路径、链接边界和资源版本。不得把桌面 `vetta-media:`、`vetta-plugin:` 等地址简单替换成任意路径下载。
- HTML、SVG、Markdown、工具结果、设计代码及插件页面均按不可信内容处理。设置 CSP、净化显示内容和危险链接；可执行预览与控制页面隔离，不能获取控制会话。
- 限制上传/响应/帧大小、连接数、认证尝试、并发工作和发送缓冲；慢客户端不会持续积压宿主内存。上传有配额、完成提交与过期清理，不允许路径穿越或覆盖竞态。
- 敏感响应不进入公共缓存，不记录凭据或原始聊天内容。Range、下载和错误响应仍需鉴权，不能只保护主 API。

## 7. 实施阶段与完成判据

1. **行为保持型宿主传输提取（本阶段已验收）**：分离 Electron 类型与平台依赖，保留现有 API 参数、错误、事件次序、订阅初值及释放行为；已用定向合同测试验证原有桥接行为，独立审计无阻断。本阶段不交付网页或网络服务。
2. **领域合同与安全网关（当前修订增量）**：按 [ADR-0129](../../../docs/adr/0129-native-web-loopback-gateway.md) 接入 Desktop 本地管理、独立浏览器授权、选定私网 IPv4 的 HTTP 网关（可选 HTTPS 回环代理）、独立 Web 构建入口和项目只读观察。首轮实现的 G1–G11 阻断已修订并补齐定向回归，当前待重新冻结后独立复审；其余领域的操作目录、稳定对象身份、快照游标、幂等及撤销语义继续逐项落实。不可把局域网 HTTP 视为公网部署方案。
3. **Web 启动与逐域同步**：共享展示与模型，接入独立客户端状态和平台适配；按矩阵完成每个领域的正常流程、冲突、重连及跨端事件，不以临时空实现填充接口。
4. **第一方复杂能力与插件兼容**：完成 PTY、多端审批、设计、浏览器、媒体及唯一执行 owner；保持第三方桌面兼容，网页未适配状态可解释。
5. **完整验收**：逐项有实现证据和实际测试结果；完成全部承诺的内置目标、安全及桌面回归后才允许将状态改为完成。仅聊天可用或仅构建成功不足以进入此阶段的完成态。

阶段可以按不重叠领域并行，但当前文档不授权新增服务部署、真实模型调用、真实用户数据访问或发布。

### 7.1 当前网关增量的范围与代价

这一增量的目标是实际串联「Desktop 开启并生成配对凭据 → 浏览器配对 → 查看同一项目列表并跟随 Desktop 的项目变化 → 刷新恢复 → 单独撤销或关闭」。它不是聊天 MVP，也不把完整目标缩减为只读项目页。

- **只读权限**：仅允许查看全部当前/归档项目的名称、宿主路径及列表变化，不授予文件读取、项目修改、会话发送或宿主执行。后续不能静默扩大这份授权。
- **先解决安全入口，再开放写入**：现有 ProjectService 的异步整份配置写回没有共享版本比较或串行协调，已复现并发修改互相覆盖。导入、批量任务及配置保存还会绕过项目服务写配置，无关设置也可能恢复陈旧项目字段；仅在网关或 ProjectService 加锁不足以闭环。当前不增加网页写入口，请求幂等不能替代内容冲突检查。
- **私网监听与临时授权**：默认关闭，HTTP 仅绑定本机选定的私有 IPv4；已有 HTTPS 代理仍使用明确的 `127.0.0.1` 上游。当前增量的配置、开启状态和浏览器授权先保存在内存，Desktop 重启后需要重新开启和配对。配对有效期 5 分钟、授权绝对有效期 1 小时，由服务端强制到期，刷新不延长；局域网明文可被截获，不可公网映射。
- **完整快照同步**：失效观察必须覆盖成功持久化的常规项目操作、导入、批量项目和配置保存，不能只依赖原有 Electron 广播或定时轮询。有界长轮询每次取得完整新快照；中间变化可以合并，游标表示这一只读投影的失效次序，不是可写 CAS 版本，也不是全应用持久事件日志。
- **安全恢复与本地管理**：Cookie 已认证的无副作用 bootstrap GET 返回独立 CSRF 到页面内存，并禁止缓存；允许没有 Origin，但提供错误、`null` 或重复 Origin 必须拒绝。业务 POST 要求精确 Origin 和 CSRF，配对采用精确 Origin、JSON 和一次性凭据保护。管理 IPC 同时检查登记控制窗口、非空顶层 frame 和可信入口 URL；网页不能调用管理操作。
- **范围必须可见**：网页明确区分已适配的项目目录与尚未接入的其他功能；不能返回空成功或将静态页面可打开表述为内置功能完整。

以上为实施合同；首轮冻结快照的验证与未通过项见 8.4，修订后的最终路由、限制和验收结果仍须另行登记。上一阶段 preload 的通过结果不覆盖这一增量。

## 8. 验收与验证入口

### 8.1 必须串联的使用流程

- **双端主流程**：桌面开启并确认配对 → 网页选择项目并打开会话 → 任一端发送，另一端显示同一回合 → 另一端停止或回答交互 → 网页刷新/断线重连 → 历史、队列及终态一致，执行次数不增加；期间两端可停留不同页面。
- **编辑与设置流程**：桌面修改文件，网页读到新版本 → 两端并发提交同一基线 → 冲突可恢复、不丢内容 → 更新业务设置后两端读到宿主确认值，草稿/主题/布局没有被擅自覆盖。
- **执行类流程**：批量任务、Team、调度和媒体生成分别覆盖启动、等待、失败、继续/重试、停止、刷新恢复；网络重试与用户新建尝试严格区分。
- **资源流程**：浏览器上传 → 宿主登记 → 两端预览/编辑/下载 → 版本失效 → 撤销后拒绝访问；覆盖本地与 SSH 项目、媒体 Range、路径穿越和链接边界。
- **PTY 与审批流程**：终端双端 attach、输入竞争、输出缺口及重连；双端审批竞答、拒绝、过期、迟到回复；只发生一次被批准的副作用。
- **插件及第一方能力流程**：安装/升级/停用状态双端一致；多个网页和刷新不重复激活；设计保存及导出、宿主浏览器操作、媒体生成预览有真实结果；旧第三方插件保持桌面工作并正确显示网页兼容状态。
- **安全与撤销流程**：错误 Host/Origin、跨站 Cookie、过期/重放配对、伪造代理头、越权对象/游标/资源访问被拒；生成中、等待输入中、慢连接、断线恢复和异步开启时撤销均收敛，独立本地任务不受影响。
- **平台边界流程**：拒绝浏览器设备授权或宿主原生权限，界面展示真实结果；不支持的系统能力不得返回成功；宿主退出/更新后正确处理失效连接和恢复边界。

## 9. 尚未决定的关键协议事项

这些事项应在对应领域编码前形成可测试合同，不能由单个适配器临时猜测：

1. **身份与部署**：当前只读增量的可选私网 HTTP / 回环 HTTPS 入口、一次性配对、不同 Cookie 属性与 CSRF、临时授权及重启失效合同见 ADR-0129；仍需核验实际实现与部署。长期授权、自动恢复开启、迁移和持久撤销尚未决定，不能从只读增量推定其安全语义。
2. **操作目录与稳定身份**：公开操作的实际名称、版本、能力分类；持久会话身份与 Runtime ID 映射；全功能所有者权限如何细分，哪些原生动作必须宿主确认。
3. **恢复与崩溃边界**：快照/事件的原子交接、游标窗口、宿主世代、去重日志持久化与保留期、已接受但结果未知的操作如何查询；不得承诺未经证明的恰好一次执行。
4. **共享执行归属**：PTY 输入和尺寸租约、断线保留期；浏览器授权撤销后，已接受队列、持久自动化、生成任务与待审批的取消/转移策略。
5. **并发内容修改**：文件、设置、设计文档和任务定义使用的版本基线、原子写入方式及冲突返回结构；外部编辑和 SSH 变更的检测边界。
6. **插件与第一方原生适配**：网页展示入口/兼容声明、隔离桥、唯一执行 owner 的演进方式；设计预览和宿主浏览器的呈现/输入合同及登录会话边界；不得以“已可加载 UI”代替执行安全或完整能力验收。
