# ADR-0131：Desktop 开发版默认共享本机正式数据

## 状态

已接受

## 背景

Desktop 开发启动器原本默认使用 `~/.vetta-dev`，正式安装版使用 `~/.vetta`。调试与本机已有项目、会话或设置相关的问题时，开发版看不到实际数据；开发者必须额外切换到已有的 `dev:home` 入口。与此同时，共享数据的两个实例可能并发写入，开发版此前还会默认跳过 App Action 审批。UI 验证脚本及 Debug 的模型配置播种依赖隔离开发目录，不应因为普通启动入口改变而自动触及真实数据。

## 决策

1. Desktop 的普通 `dev` 启动默认选用 `VETTA_CONFIG_DIR=.vetta`，同时将 Electron user data 指向同一目录下的浏览器配置。`dev:home` 保持兼容，`dev:isolated` 显式使用 `~/.vetta-dev`。现有的环境变量覆盖仍优先于默认值，不迁移或复制两套目录中的数据。
2. 共用正式目录时，开发进程默认不启用 App Action 自动审批；隔离目录继续保留开发期默认行为，开发者仍可显式覆盖该开关。这个选择不改变一般文件读写或其他权限模型。
3. Fresh、Debug 与 Dev UI 验证 Profile 继续隔离。Dev 只附着显式启动的 `dev:isolated` 实例；Debug 只从 `~/.vetta-dev` 播种或同步白名单中的模型配置，不自动读取正式版凭据和会话。
4. 不在普通 `dev` 中启动、停止或修改已运行的正式安装版。使用共享目录的开发者必须先退出正式版；现有单实例锁不能可靠阻止两个进程同时写入同一目录。

## 备选方案

- 维持隔离默认值、仅用 `dev:home`：对调试本机真实数据的需求仍需每次手工切换，容易误以为开发版缺少数据。
- 复制正式数据到隔离目录：需要处理凭据、动态数据、同步与清理，复制后的状态又可能偏离真实问题；不符合直接调试目标。
- 将所有验证 Profile 一并切换到正式目录：自动化或调试会话可能影响真实数据，且违背验证实例的隔离契约。

## 后果与验证

普通开发版会直接读取并可能改写本机正式数据，包含项目、会话与设置；启动前必须关闭正式版，必要时先备份。已有 `~/.vetta-dev` 数据不会被删除或迁移，仍可通过 `dev:isolated` 访问。启动器的定向合同测试覆盖默认共享、显式隔离、验证实例隔离、浏览器目录覆盖与审批默认值；不通过启动真实 Desktop 或访问真实 Provider 验证该决策。
