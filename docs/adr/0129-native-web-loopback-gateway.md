# ADR-0129：原生 Web 的回环网关与独立浏览器授权

## 状态

实施中，首轮只读网关实现的独立审计未通过，G1–G11 已修订并补齐定向回归，待重新冻结后复审，尚未完成实现验收。本记录确定当前增量的边界，不代表完整原生网页客户端已可用。实际接口、默认限制和验证结果以实现、测试及[实施合同](../../apps/desktop/docs/native-web-client.md)的验收记录为准；不能通过降低本记录的安全要求来代替修复。

## 背景

[ADR-0128](./0128-desktop-host-api-transport-boundary.md) 已分离 Desktop 客户端 API 装配与 Electron 传输，但内部 `channel: string` 和 `sendSync` 不是网络公开合同。直接把这层接口映射成 HTTP 或 WebSocket，会把本机权限、窗口身份、文件路径和进程生命周期带到不可信浏览器边界。

用户确认 Desktop 常驻、单用户使用；原生网页最终需要完整内置功能，与 Desktop 共用业务状态，但页面、选择和草稿独立。HTTPS 由已有可信反向代理或带 HTTPS 的 VPN 入口提供。普通 VPN 不替代 HTTPS，Vetta 不在这一增量管理证书。

项目是适合验证共享事实源的第一个领域：[ProjectService](../../apps/desktop/src/main/projects/project-service.ts) 集中了常规项目操作并在写入后广播，但项目导入、批量项目注册/回填和配置保存仍有直接调用 [writeDesktopConfig](../../apps/desktop/src/main/config/desktop-config-store.ts) 的路径。仅观察 ProjectService 广播会漏掉这些真实变化。同时，读取配置、修改快照再写回的现有流程没有跨操作串行或版本比较；开放网页写入会增加丢更新风险，仅给网络套一层幂等 ID 不能解决旧快照覆盖问题。

## 决策

### 1. 一个宿主，两个受约束的入口

- Main 领域服务仍为业务事实源。Electron IPC 和网络入口分别调用领域服务，不反向导入 IPC handler，不伪造 `WebContents`，不创建第二个 Runtime 或业务数据库。
- Desktop 本地管理入口负责配置、开启、生成配对凭据、查看授权、撤销和关闭。该入口继续经过 preload 的 token 保护，并在 Main 同时校验宿主登记的控制窗口、非空顶层 frame 和可信入口 URL；预览、webview、子 frame、已导航离开的页面均拒绝。仅检查 URL、token 或客户端自报身份都不够，管理能力不进入普通浏览器操作目录或通用 Action/capability。
- 浏览器只有显式登记的网络操作。未知操作、版本和不符合 Schema 的参数拒绝；不能传入任意 IPC channel、Action RPC token、Provider 凭据或 privileged 来源。
- 第一增量只授予项目目录读取和变化观察，不授予项目修改、文件读取、会话执行、终端或插件管理。后续扩展执行能力须重新定义授权，不静默扩大已有只读授权。

### 2. HTTPS 入口与回环上游

- 默认关闭，不监听。用户在 Desktop 明确开启后，只绑定指定的 `127.0.0.1` 端口；端口冲突或配置错误直接失败，不自动绑定所有接口或改用另一个地址。
- 用户配置外部 HTTPS Origin，并为控制页使用专用可信 hostname。Cookie 不按端口隔离，不能把同 hostname 的不可信预览换一个端口就视作安全隔离。代理须把该站点转发到本机回环上游并保留预期的 Host；代理位于其他机器时，必须另有受控的本机转发链路。
- 网关按已配置的 Host 和 Origin 精确校验，拒绝重复或歧义的安全相关头。忽略 `Forwarded` / `X-Forwarded-*` 的身份与权限含义，既不根据其值推断可信来源，也不因为正常代理携带这些头就拒绝请求；不反射任意 CORS Origin。
- 所有 POST 要求与配置精确一致、非 `null` 的 Origin。静态导航和无副作用的认证 bootstrap GET 可以没有 Origin，但带有错误、`null` 或重复 Origin 时必须拒绝；bootstrap 仍要求有效 Cookie 并禁止缓存，不因允许缺省 Origin 而允许匿名读取状态。Host/Origin 防护是认证的补充，不是用户身份。
- 回环 HTTP 无法自行证明外部连接使用了 TLS；HTTPS 代理及其受控上游是部署信任边界，必须在部署说明和验收中单独核对。

### 3. 独立、短期、可撤销的浏览器授权

- 从可信 Desktop 管理入口生成高熵、短期、一次性配对凭据，绑定当前世代、Origin 和明确只读范围；本增量的设计默认有效期为 5 分钟。凭据经浏览器同源 JSON 请求提交，不放在 URL、日志或浏览器长期存储中。新邀请替换旧邀请，消费邀请与创建授权原子完成，竞争兑换只成功一次。
- 每次配对产生独立授权；Cookie 使用 `__Host-` 前缀、`Secure`、`HttpOnly`、`SameSite=Strict` 和 `Path=/`，不设置 Domain。服务端保存必要授权元数据及凭据摘要，不复用本机 RPC 或手机 Relay 的秘密。
- 独立、不可预测的 CSRF 凭据绑定认证会话，由 Cookie 已认证、无副作用且 `no-store` 的 bootstrap GET 返回页面内存；同 Cookie 的多个标签页须可同时使用，刷新不能通过轮换唯一 token 使其他标签失效。不能要求客户端先提供尚未取得的 CSRF，也不能把 HttpOnly 会话凭据本身当作 CSRF。配对入口由精确 Origin、JSON-only、全局有界认证尝试和一次性凭据保护，其余业务 POST 同时校验会话和 CSRF。
- 授权具有绝对有效期与数量限制；本增量的设计默认绝对有效期为 1 小时，由服务端强制执行，刷新或重连不延长期限。到期、退出、撤销或功能关闭后先使授权失效，再拒绝新请求并中止所属等待和连接。异步读取完成后、敏感响应发出前再次检查授权。
- 这一增量不持久保存开启状态、配置和浏览器授权，Desktop 重启后需要重新开启与配对。代价是使用上的额外步骤，收益是不会产生尚未定义迁移和撤销语义的长期远程凭据，也不会通过整个 Desktop 配置的旧快照写回引入新的覆盖路径。
- 配对说明必须明确：浏览器将看到全部当前与归档项目的名称和宿主路径；这不等于文件沙箱，也不授予执行权限。

### 4. 项目同步采用完整快照与失效游标

- 传输无关的变更观察必须覆盖真正的项目持久化写入边界，包括常规项目操作、导入、批量项目注册/删除/回填和配置保存，不能只订阅现有 Electron 项目广播。保留原有 Electron 行为；观察者相互隔离，某一端退订或回调失败不影响其他端和本地通知。
- 读取仍调用唯一 ProjectService。传输字段显式挑选，不序列化整个 DesktopConfig，也不因内部对象新增属性自动扩大网络响应。
- 第一增量使用认证的 JSON 请求与有界长轮询。每次返回完整项目快照和流世代/游标；变化信号可以合并，不声称保留每次中间变更的日志。
- 在异步读取前建立观察关系；读取期间检测到变化就重新读取或明确要求重新同步，不能给旧快照贴上新游标。持续变化与读取失败要有界退出和明确错误。
- 游标只表示只读投影的失效次序，不是可写 CAS 版本。刷新、宿主世代变化或未知游标重新获取完整快照，不重放业务副作用。
- 并发项目修改、文件/设置冲突、发送幂等及有序会话流仍需各自的领域合同；本增量不得宣称它们已由项目长轮询解决。

### 5. 资源与生命周期有界

- HTTP 头、请求体、并发请求、连接、配对尝试、每授权等待数、响应大小和等待时间均设置上限。限流不能依赖可伪造代理头，也不能让慢客户端持续积压内存。
- 服务自行协调共享启动/停止 Promise 与取消语义。关闭和撤销先阻止新准入，再取消等待、释放观察关系和所属连接；并发清理调用应等待同一次清理完成。异步启动过程中关闭，迟到的启动结果也必须被回收；不能仅靠 Renderer 卸载或退出回调去重来保证清理完成。
- 应用退出接入同一清理路径。浏览器断线和取消长轮询不取消独立 Desktop 工作；本增量没有浏览器创建的执行任务。
- 静态服务只发布独立 Web 构建产物，按明确资源清单提供页面和资产，不把 Desktop Renderer、项目文件、配置、源码或 source map 作为公共目录。
- 对路径穿越、非法编码与符号链接越界失败关闭；控制页面配置 CSP、`frame-ancestors`、`nosniff`、Referrer 策略和敏感响应禁缓存。项目名等不可信文本不作为 HTML 执行。

### 6. 共享技术栈，而非另建产品副本

Web 入口继续放在现有 Desktop 应用工程，复用 React、基础 UI、i18n 和正式业务类型，采用独立 Vite 构建目标，不复制完整 Desktop 页面，也不载入假 `window.vetta`。当前入口只实现配对和项目目录，准确展示未适配范围、断线、重试、过期和撤销；后续按完整目标矩阵逐域扩展。

## 备选方案

- **直接代理全部 preload API**：实现快，但内部参数、权限和生命周期假设不适合网络边界，拒绝。
- **沿用手机 Relay 或本机 Action RPC 凭据**：两者的授权、恢复和客户端身份合同均不同，混用会扩大既有信任域，拒绝。
- **立即开放项目写操作**：会暴露已有 read-modify-write 并发问题。先定义领域版本与共享写入协调，再开放，不能依靠请求去重替代冲突检查。
- **一开始使用通用 WebSocket RPC**：后续流式领域可能需要，但项目完整快照只需单向变化通知。有界长轮询先缩小握手、背压和通用操作分发的安全面；不会因此承诺它适用于全部领域。
- **持久授权并随 Desktop 自动启动**：需要配置迁移、凭据落盘和重启撤销合同，不在这一增量实现。未来如增加，必须保持显式启用与最小授权。
- **远程屏幕或独立 Agent 后端**：分别不符合原生控件与唯一业务事实源要求，拒绝。

## 验证要求

1. 真实内部装配流程：本地开启 → 一次性配对 → Cookie/CSRF 恢复 → 两个浏览器观察同一项目服务 → Desktop 修改项目 → 两端取得最新快照 → 单端断开不影响另一端 → 撤销与关闭后拒绝访问；补充绕过常规 ProjectService 写入的导入、批量项目和配置保存路径通知覆盖。
2. 认证与网络边界：错误/缺失/重复 Host、Origin、Cookie、CSRF，伪造代理头，配对重放与竞争，到期、数量限制、未知操作、超大请求、慢连接和静态资源逃逸。
3. 竞态：读取期间变更、取得快照后尚未等待时变更、撤销与读取交错、异步开启与关闭交错、客户端退出后迟到响应。使用明确同步点和可控时钟，不依赖任意等待。
4. 真实组件接线：本地管理表单的开启、配对、撤销、失败恢复；Web 配对、实时列表、刷新、断线和认证失效；不只测试抽出的纯函数。
5. 运行受影响的 preload、项目、退出、构建合同、定向行为测试和仓库完整质量门禁。独立审计没有阻断后才能验收此增量。
6. HTTP 集成测试和组件测试不能替代真实 HTTPS 代理、浏览器 Cookie/CSP 及完整双端功能验收。未执行的环境验证必须明确列出；不启动用户实际 Desktop、Provider 或代理来冒充隔离测试。

### 首轮实现审计记录

首轮冻结实现已完成开发自测和独立审计，但未通过验收。审计确认了授权在关闭期间复活、管理 IPC 来源检查不足、请求取消/截止和生命周期协调缺失，以及项目持久化通知覆盖不全的 G1–G5 阻断；G6–G11 涉及多标签认证、授权期限、严格协议、代理兼容与两端状态恢复。完整清单、开发/主控/审计证据及复审条件见[实施合同第 8.4 节](../../apps/desktop/docs/native-web-client.md#84-网关增量当前的验证状态)。

主控的独立 Web 构建、入口/脚本/样式装载和打包合同通过，不证明 CSS 引用资源全部可服务或真实浏览器安全行为已经通过。首轮完整 `bun run check` 仍有两项格式/导入错误；所有审计项须形成持久回归并在修订冻结后独立复审。原有项目并发丢更新另行跟踪，不因只读网关修订而关闭，也不以它为由延后本轮通知覆盖修复。

### 本轮修订记录

G1–G11 已按上面的要求逐项修订（清单与对应回归见实施合同第 8.4 节）：关闭与更换配置先递增世代并作废凭据再拆监听器；管理 IPC 做三重来源校验；新增每授权并发上限，撤销与关闭同时中止在途观察；开启/关闭/改配置/退出收敛为同一条完成链，失败留下错误状态；项目观察点移到唯一的配置落盘边界并只比较项目投影；bootstrap 恢复为无副作用 GET 与稳定 CSRF，授权绝对有效期回到 1 小时；协议与游标校验收紧，转发头不再影响 Host/Origin 判定；管理页保留草稿与错误并随兑换刷新授权，Web 入口改为自动重连并在授权失效时退回配对。CSS 相对 URL 与 cursor 资源清单问题同时修复。

本轮重跑了受影响的定向范围、Desktop 全量测试（753 个文件 / 3751 个用例，0 失败）与完整 `bun run check`（退出码 0，含五路类型检查、全部架构守卫与 mobile lint）；具体数字见实施合同第 8.5 节。首轮阻止验收的两项门禁错误已消除，首轮因本机缺少 `bun` 而失败的两项测试也已转为通过。这些是本轮修订的自测证据，不是验收结论：重新冻结后的独立复审、真实 Desktop、HTTPS 代理与浏览器 Cookie/CSP 验证仍未完成。

## 后果

安全入口、授权和项目观察可以独立验证，也保留了后续增加领域能力的边界。代价是这一增量只提供只读项目目录，重启后重新配对，并且外部 HTTPS 部署仍需用户维护。完整网页的会话、文件、终端、审批、Agent/Team、调度、设计、媒体、浏览器和插件展示仍按原实施合同完成；不能把本记录或构建通过当作完整交付。
