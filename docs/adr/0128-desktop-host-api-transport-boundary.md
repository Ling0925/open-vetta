# ADR-0128：Desktop API 装配与 Electron 传输分离

## 状态

已接受；本次只实施客户端 API 装配边界，不代表原生网页客户端已经可用。

## 背景

原生网页客户端需要与 Desktop 共用宿主业务能力和状态，而不是运行第二套 Agent、复制会话数据，或通过远程桌面传输屏幕。现有 preload 将全部 `create*Api` 工厂直接装配到 Electron `ipcRenderer`，工厂的类型依赖也绑定 Electron。浏览器若另写一套同形 API，会重复维护参数映射、事件解码、订阅初值缓冲和清理行为。

但客户端 API 装配并不是可直接发布的网络合同。当前主进程入口中仍有固定主窗口投递、窗口拥有终端、插件执行和 UI 同时激活等约束。仅用 WebSocket 模拟 `ipcRenderer`，不能解决浏览器认证、输入校验、权限、客户端生命周期和双端一致性。

## 决策

1. 将 raw `DesktopApi` 的聚合装配提取为 `createRawDesktopApi`。它接收窄的 `HostTransport` 和文件路径适配器，不导入 Electron 运行时；Electron preload 负责提供实际适配，并继续通过原有单次领取令牌的 `createHostAccessGate` 暴露 API。
2. `HostTransport` 只表达现有请求、单向发送、同步初始化读取、事件监听和独立退订语义。保留现有 channel、参数、返回值、同步与异步行为、错误传播及事件解码；此次不改变主进程处理逻辑或持久化格式。现有 i18n 首帧初始化的 `sendSync` 仍由 Electron 实现；未来浏览器应在装配前取得可信启动快照，不得通过同步网络请求或固定空值冒充这一合同。
3. `HostFilePathAdapter` 单独承载 Electron 的 `webUtils.getPathForFile`。浏览器文件名不能被解释为宿主绝对路径；后续 Web 适配必须使用上传或已授权资源引用，不能伪造本地文件路径。
4. raw API 工厂是受信任的客户端装配入口，不是权限闸门。不得直接暴露给插件，不得用它移除 `hostAccess` 保护，也不得据此开放任意 IPC、调试调用、凭据读取或宿主对象。
5. 后续网络适配必须有显式业务操作目录、边界校验、逐操作授权和明确错误合同，由 IPC 与 Web 各自装配到同一个宿主领域服务。浏览器输入不能决定内部调用来源、`WebContents` 身份或特权能力。

## 备选方案

- **为 Web 复制所有 preload API**：能暂时隔离 Electron，但会形成两份参数映射、订阅逻辑和 API 聚合，后续桌面变化容易遗漏网页消费方。
- **将 `IpcRenderer` 强制转换为浏览器传输实现**：掩盖真实依赖范围，无法机械核对浏览器缺失的方法，也会鼓励把桌面 IPC 当作网络安全合同。
- **通用 WebSocket 代理全部 IPC**：不是本次选择。内部接口依赖受信任窗口和本机生命周期，缺少浏览器网络边界所需的合同，不能因接口数量多就绕过鉴权和校验。
- **另建 Agent 后端或远程桌面镜像**：不符合两端共享同一宿主状态、独立使用原生界面的目标。

## 后果

- Desktop 继续使用 Electron IPC，Renderer API 和现有插件调用方式不变；不新增监听端口、网络服务、运行时实例或数据迁移。
- 客户端装配可在无 Electron 运行时的测试环境中验证，订阅竞态和退订行为不必另写一份模拟业务实现。
- 这一步不解决主进程的客户端订阅隔离、原生能力适配、插件多端展示、认证网关及可靠同步。上述内容仍须按[原生网页实施合同](../../apps/desktop/docs/native-web-client.md)逐项实现和验证，不能将本记录当作完整功能的完成声明。
- 用户已确认内置功能以完整网页支持为目标；第三方插件保留桌面兼容并逐步适配网页。网页不得再次完整激活旧插件的执行贡献，也不能用返回成功的空实现冒充支持。

## 验证要求

- 真实 raw API 装配下验证会话订阅初值、流式事件、发送与停止，以及项目、配置、文件二进制和终端订阅的代表性调用。
- Electron 适配验证监听器身份、重复注册与独立退订，保持同步抛错和异步拒绝语义。
- 保留并实际运行原有 `hostAccess`、preload 工厂和订阅缓冲测试；执行仓库质量门禁。
- 浏览器网络、双端同步和完整功能验收属于后续实现，不能由本阶段测试替代。
