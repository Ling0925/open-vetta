# Codex 安装测试版

本分支提供可安装的工程测试版，不是正式发布。安装包生成和打包后检查成功后，文件出现在 fork 的
`codex-preview-installers` Actions 运行页的 **Artifacts** 中。失败或未完成的构建不能视为已经有安装包。
Mac Apple Silicon 选 `darwin-arm64`，Intel Mac 选 `darwin-x64`，普通 Windows 64 位选 `win32-x64`。
每份制品附带对应源码提交、版本、安装说明和 SHA256SUMS；不要用上游 Release 替代该测试产物。

## 安装和回退

这是未签名、未公证的本地测试产物，系统可能显示来源警告。先核对来源和摘要，不要全局关闭 Gatekeeper、
SmartScreen 或防病毒。如果公司策略禁止未签名应用，应通过公司的签名或分发流程处理。

先完全退出正在运行的 Vetta，再备份 Vetta 数据目录（默认 `~/.vetta`）和当前应用；不要同时运行正式版与测试版。
Mac 使用 DMG/应用 ZIP，把应用放到固定位置后启动；Windows 解压整份应用 ZIP 到独立文件夹，运行其中的 Vetta.exe，
不要只复制 exe 或单独移动版本目录。该构建不会自行覆盖安装、创建发布 tag、上传 Release 或向正式更新源发布。
需要回退时退出测试版，重新打开原应用；恢复数据备份前先另存测试产生的内容，以免覆盖新的工作。

**应用设置和凭据存储仍与原 Vetta 共用**，便于复用已有网关；仅 Codex 的默认历史目录独立。
不能把它理解成整个应用数据完全隔离。此测试构建不包含语音输入模型，其他功能仍须按各自限制使用。

## 首次配置

入口为 **新建会话 → 使用 Codex 预览**。
安装包内置固定的 Codex 0.157.0 原生程序、相邻执行资源和许可证，不要求用户额外安装 Node、Bun 或 Codex。
页面自动填入该程序路径、版本和独立 Codex 数据目录；读取这些默认值不会保存配置、登录或启动模型。

模型来源选择“使用 Vetta 已有网关和模型”，选择已经配置好的 Responses 模型，再选择一个专门测试的本地项目目录。
不要选择家目录、Vetta 数据目录或包含登录资料的目录。先保持本地只读，点击“确认并保存配置”并核对原生确认窗口。
保存完成后再点击“新建 Codex 会话”，然后发送任务。保存时才会创建默认的独立历史目录。
复用网关不需要另行登录 ChatGPT，也不要求再填写网关密钥。模型设置仍以 Vetta 原有配置为唯一来源。

默认 Codex 数据目录为 `<Vetta 数据根>/desktop-app/codex-runtime/home`，不会复制系统 Codex 的 config、auth 或 .env。
旧手动配置不会自动被覆盖。需要换成内置程序时，可明确点击“使用内置 Codex 和独立历史目录”并重新保存；
旧 Codex 会话不会自动迁移，恢复时仍需与原来的版本、目录、工作区及供应商配置匹配。

## 建议第一轮测试

从临时项目开始，先让它列出文件并解释一个文件，确认流式文字和工具结果正常。
再测试连续追问、生成中停止、停止后发送新任务、离开再返回、关闭连接和恢复原会话、退出后重新打开应用。
准备阶段停止也应阻止原指令晚到后继续运行。结果不确定时先关闭并恢复历史核对，不要直接重复提交同一任务。

确认只读流程后，才在有 Git 备份的测试项目中选择工作区写入。遇到审批先拒绝一次，再对明确、无害的操作批准一次。
不要把工作区写入理解成所有操作都会弹窗；沙箱允许范围内的普通写入由 Codex 的策略决定。
停止不回滚已经完成的操作，本地只读也不能约束外部 MCP/插件的全部副作用。

当前只支持明确为 `openai-responses` 的模型、HTTPS 网关或本机 HTTP；不自动把其他协议转换成 Responses。
测试接口仍是独立预览，不替换 Native 默认引擎。附件、Native 工具/插件接线、团队、远程项目和完整历史分页尚未接入。

## 遇到问题时

保留应用版本、制品中的源码提交、系统/架构、模型协议、具体操作顺序和界面“技术信息”中的错误码。
提供日志前删除网关密钥、Authorization、Cookie、个人文件内容和内部地址。
`CODEX_BUNDLE_INVALID` 表示安装资源、版本或平台不匹配，应核对整包；`VERSION_MISMATCH` 表示运行的程序版本与配置不同。
网关配置变更会阻断旧连接，先核对后显式重开，不会悄悄回退官方服务。

## 本地构建

在完整检出仓库、安装仓库要求的 Bun/Go 等构建依赖后，执行：

```bash
bun install --frozen-lockfile
node apps/desktop/scripts/build-codex-preview.mjs
```

脚本在临时目录安装固定 Codex 分发包，只使用已有 Desktop 构建流水线，最后生成不发布的本机架构测试包。
不会修改仓库锁文件、全局 Codex 或用户认证目录。稳定发布仍遵循原有完整质量与签名门槛。

## 验证边界

流水线保留完整质量检查，并单独运行配置/审批/取消/表单合同测试、实际应用构建和打包后的 Electron 入口检查。
只有构建与安装入口检查通过的目标才上传测试制品；完整质量检查的结果单独呈现，工程测试包不等于正式发布准入。
安装入口检查验证实际 Renderer/preload/Main 接线、内置二进制版本和默认配置不自动保存，不调用真实模型。
自建网关的协议兼容、真实任务效果、跨平台所有权限场景仍需本轮人工测试，不能凭安装成功宣称全面验收。
