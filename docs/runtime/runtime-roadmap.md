## R1：统一任务准入与输入身份

建议未来工作项标题：`[Runtime R1] 统一 Turn 准入与稳定 inputId / expectedTurnId`。
依赖 R0.2 的双后端合同，Native 沿用并进一步收敛 PR #1 的修复。

- 将 send、steer、continue、retry、send-now、后台唤醒的准入集中为唯一所有者。
- 区分输入接受、持久化提交、任务完成；稳定 inputId 贯穿队列和消息，定义重复提交回执。
- 操作指定 expectedTurnId / expectedPreviousTurnId；被拒绝的输入不能修改模型或权限设置。
- 设计队列到 Conversation 的提交/恢复协议；不能仅凭内存预留宣称 exactly-once。

验收：并发两个输入、停止后马上发送、旧任务迟到收尾、准备失败、持久化失败、崩溃重开、重复客户端请求。
真实 Pipeline 与事件投影参与测试，只在模型与外部 I/O 边界替身。

## R2：稳定 Item 与权威终态

建议未来工作项标题：`[Runtime R2] 稳定条目身份、终态和版本化快照恢复`。
依赖 R1。扩展现有 eventId/sequence，不另建第二套事实源。

- 明确 Thread/Turn/Item 身份与实例代际；消息与工具结果按 ID 合并。
- 终态不可被迟到 delta 倒退；历史快照包含版本边界，再衔接增量。
- 进程重启后以新实例代际重建，不将内存序号当持久化日志。
- 持久化最终消息/工具结果/输入/终态；Token 流不要求逐条落盘。

验收：乱序、重复事件、丢失增量、快照加载并发流式生成、切换后台会话、进程重启，无重复气泡和假 running。

## R3：可靠取消与受控工具并发

建议未来工作项标题：`[Runtime R3] 工具取消确认、结果未知状态与有界并发`。
依赖 R1/R2。先验证取消，再开放并发。

- 工具能力明确声明并发与副作用类别；默认串行，只对白名单只读工具有限并发。
- 写工具保持排他，后续可按资源冲突加锁，结果始终按调用 ID 配对。
- 区分取消已请求、实际终止、已成功、结果未知；已成功副作用不可被重试覆盖。
- 授权等待、实际执行、子进程回收共用取消归属；stop 后不得启动新工具。

验收：读读并发、读写冲突、审批中 stop、不响应 signal 工具、迟到结果、工具已成功但模型失败，终态恰好一次。

## R4：上下文、压缩与循环收敛

建议未来工作项标题：`[Runtime R4] 最终请求预算、协议完整压缩与无进展检测`。
依赖 R1/R2；保持现有摘要/固定上下文/扩展能力。

- 预算计算落到最终请求（system/tools/attachments/output reserve），而不是只数聊天文本。
- 压缩保留 tool call/result 配对、用户限制、已完成动作和剩余步骤。
- 分开记录继续执行原因：工具结果接续、用户插入、错误恢复、后台通知。
- 按 Provider 能力选择远端或通用摘要；成功但无进展的重复要可诊断/暂停，允许合法轮询。
- 不无说明地更改 Native 的现有 opt-in 循环预算；达到预算须保留进度与明确结束原因。

验收：超大工具输出、压缩中插入消息、压缩失败、跨模型切换、重复工具调用、合法轮询和长任务继续。

## R5：连接身份与缓存正确性

建议未来工作项标题：`[Runtime R5] 连接归属隔离、凭证代际失效与缓存验证`。
正确性先于预热与增量请求。R0.2 配置指纹不替代实际账号、端点与配置内容的身份验证。

- 连接归属覆盖 Provider/endpoint/账号身份/凭证代际/session，不把 Token 放进键或日志。
- 账号、端点、撤销或权限变化使旧连接与 previous_response_id 失效。
- 验证最终请求的稳定工具顺序、提示词前缀和注入去重；按服务端能力开启优化。
- 不将 API-compatible 当成全部扩展兼容，未知能力保守降级。

验收：同 session 换账号/endpoint、OAuth 轮换/撤销、缓存布局改变、服务端拒绝增量请求，不串账号、不重复任务。

## R6：授权、沙箱与重试

建议未来工作项标题：`[Runtime R6] 统一授权/沙箱/重试并即时执行权限收紧`。
依赖 R1/R3。Codex 与 Native 都必须满足共同的宿主授权合同。

- 审批绑定任务、工具、规范化参数、资源和策略版本；不把审批当无限复用 Boolean。
- 用户限制收紧、操作参数改变、撤销和会话结束使旧授权失效。
- 沙箱拒绝后不得自动提高权限；重试必须重新遵守当前权限。
- 明确 MCP/插件远端副作用边界；审批 UI 缺失、断线或超时必须拒绝。

验收：先允许提交后改为只检查、审批中改参数、审批中停止、断线后晚到批准、MCP 权限变更、沙箱拒绝后重试。

## 合并与发布门槛

每个阶段 PR 提供：实际完成范围、不能做的操作、兼容/回退方案、变更说明、测试命令与真实结果。
Issues 暂缓，不伪造关联。未完成真实二进制或全仓门禁的切片保持 Draft，不因有单元测试就宣称桌面已可用。
性能对照分别测同模型真实任务与确定性的故障测试；不把模型质量差异算作 runtime 收益。
