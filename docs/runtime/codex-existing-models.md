# Codex 预览复用 Vetta 现有网关配置

## 使用路径

在 Codex 预览配置页选择「使用 Vetta 已有网关和模型」，从当前模型列表中选择已配置的模型。
新配置默认使用这条路径；已经保存的旧 Codex 目录配置保持原模式，不自动迁移。
界面仅保存 `vettaModelKey` 引用，不重复收集网关地址、密钥或自定义请求头。
Codex 程序、精确版本、工作目录及独立数据目录仍是运行时自己的配置。

复用模式下，Codex 数据目录用于其会话历史和运行配置，不需要另行写入网关 API Key 或登录 ChatGPT。
用户原有的 `.env`、`auth.json` 和 `config.toml` 不被此功能复制或改写。
独立目录中已有的 MCP/插件仍可能有外部副作用，不能把本地只读沙箱解释为整个生态的只读保证。

## 数据与执行所有权

```text
现有 ModelSettingsService / Credential Vault
        │ 读取选中的供应商与模型；每次请求重查
        ▼
Vetta 主进程 ── 临时、鉴权的本机 Responses 转发 ── 已配置网关
        ▲                     ▲
配置页只选引用         Codex App Server：会话、工具、Agent Loop
```

供应商地址、实际模型 ID、凭据及请求头以原有 Vetta 配置为唯一来源。
别名用来选择，真正发往网关的是 `modelId ?? id`。传输通过现有 `resolveProviderFetch`，保留应用代理和供应商直连例外。
不新增第二套凭据存储，也不让通用 Node 适配器读取 Desktop 设置。

真实网关密钥仅由主进程解析并用于上游 HTTP 请求；不会作为子进程参数、环境变量或 Codex Provider 配置传入。
Codex 只获得一个随机的 loopback 地址和本机临时 Bearer Token。该 Token 不是网关密钥，关闭时立即撤销；
它可能被 Codex 记录在自己的配置/历史中，因此不是无凭据运行，也不承诺抵抗恶意同用户本地进程。
网关模式下，子进程不继承 HTTP/HTTPS/ALL_PROXY，避免将本机令牌误发给代理；上游代理由 Vetta 自己处理。

## 支持范围与保守拒绝

当前只接受 Vetta 设置中明确列出的、有效 API 为 `openai-responses` 的模型。
不会因为地址看起来兼容 OpenAI 就将 Chat Completions、Anthropic 或 Azure 等配置强行当成 Responses。
网关本身还需正确支持工具调用结果、流式响应和所用的压缩请求；读取模型列表成功不等于该协议已验证。

允许 HTTPS 网关和本机 loopback HTTP；非本机明文 HTTP、含用户名/密码/查询/fragment 的地址不接受。
Base URL 应是 API 根路径，而不是已经包含 `/responses` 或 `/chat/completions` 的完整操作地址。
不支持本功能中的 `!command` 凭据求值、非空模型 overrides、未知推理等级和冲突/连接级请求头；
遇到这些配置明确拒绝，不静默丢弃后继续发送。

自定义头按原配置解析，但 Host、Cookie、代理认证和 hop-by-hop 等头不能由模型配置改变转发边界。
`authHeader=false` 保持原义：不自动生成 Bearer，可使用已配置的自定义认证头。
密钥只在主进程取用，列表和 IPC 不返回 credentialRef、apiKey、headers 或内部凭据修订哈希。

## 变更、停止和恢复

每条本机转发请求先重新解析选定配置并核对身份和凭据修订。供应商设置事件会撤销已打开的连接，
取消上游在途请求；未收到事件但读到变化、删除或凭据不可用时，也会阻断后续请求。
不会自动改走其他模型、官方服务、另一个供应商或未经过确认的新端点。
关闭旧会话、核对配置并显式重开后，才会读取新凭据。

会话关联文件的 profile 指纹额外包含非秘密的供应商/模型身份，不包含随机端口、本机令牌或真实网关密钥。
未选择 Vetta 模型的旧模式不增加该字段，保留原有指纹。
配置身份不等于网关内部账号的认证证明；同一 credentialRef 下的账号变化、外部网关路由变化，仍属于后续身份核验范围。

本机代理仅监听 127.0.0.1，要求随机令牌、精确 Host，并拒绝浏览器 Origin/Sec-Fetch-Site 请求。
只转发 POST `/v1/responses` 和 `/v1/responses/compact`，校验模型固定为所选实际 ID；
请求体有 16 MiB 上限，最多 4 个并发转发，有总时限；不跟随重定向，不自动重试。
客户端断流和关闭会取消上游 HTTP 请求。已经完成的外部效果不被回滚，也不保证服务端立即停止已接受的计算。

HTTP 错误正文以分类代码替代，避免意外反射网关密钥；正常成功流由协议原样传递，不能把这解释为对供应商全部输出的秘密扫描。
清理会同时尝试关闭本机转发与所属 Codex 后端；关闭未确认时不允许再创建另一个所有者。

## 实现范围

- Desktop `model-source`：现有模型引用、兼容性和非秘密选择列表。
- Desktop `model-source-host`：接现有设置服务、Vault 求值、变更通知及代理路由。
- Node `provider-bridge`：loopback HTTP 生命周期、鉴权、流式转发和取消。
- Codex `runtime` / `stdio`：按明确的自定义 Provider 启动/恢复并验证返回绑定；只对该模式去掉子进程代理。
- Desktop `shared-model-backend`：将原有 Host Backend 与一个临时桥接绑定，不再实现 Agent Loop。
- 配置表单：只选择已有模型引用；缺失/失败/不兼容时保留输入，不偷偷切换模式或模型。

本次在独立环境执行了 31 项实际源代码的行为测试，全部通过；其中包含两个实际 HTTP 端点之间的流式/断流测试，
以及从现有配置选择、别名映射、工具结果回传到密钥变更阻断与显式重开的连续流程。
外部网关为确定性 fixture，不访问真实网关或模型。只有 Vitest 测试注册改为 node:test，
连续流程的一处公开包导入映射到同一份真实桥接源码，不使用重写的转发算法。

定向严格 TypeScript 检查覆盖模型解析、DTO 校验、共享 DTO、桥接及上述三个测试文件的转换副本。
这不覆盖 Electron 主进程装配、React、全部 workspace 类型、所有旧测试或实际 Codex 二进制。
另有 4 项真实 React 表单测试和 2 项真实 Codex 适配器/子进程 fixture 测试已随补丁提供，但本环境没有完成运行。

## 后续修复：准备阶段也属于可取消任务

配置读取、凭据校验与实际 Turn 启动现在由同一个准入对象持有。用户在网关校验尚未返回时停止或关闭，
会立即取消等待；晚到的校验结果不能再启动原任务，也不会因为取消一个任务就撤销仍然有效的网关配置。
停止确认和任务收尾未结束前不能接收下一项工作；外部执行失败、结果未知和清理失败不会改写成“已停止”或“已关闭”。

本轮验证与六项改造的实际进度见 [取消与收尾验证](codex-cancellation-validation.md)。
这只是统一任务准入与可靠取消的一部分，不代表 Native 全部入口、持久化 inputId 或完整 Electron 验收已经完成。
